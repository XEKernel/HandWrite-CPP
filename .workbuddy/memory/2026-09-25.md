### 实现

- `core.cpp`：
  - 几何算法：`sample` 线性插值 + 端点夹取（不外推）+ 切线角；`normalize` 排序→合并近点→移动平均（端点不动）；
    `resampleByArcLength` 按累计弧长均匀取样；`build` 把各关键曲线重采样到 64 点后逐点线性混合
  - `drawTextWithPerturbationStatic`：逐字 `sample(x)`，`drawY = y + (curveY - guideY0) + perturbY + warpOffset`，
    `theta = perturbTheta + curveAngle`（叠加不覆盖）；删除线标记同步走 theta
  - `renderPageStatic`：`useCalibration` 拆成 `anchorsValid` 与 `useWarp = anchorsValid && !guidesValid`

    `lerp(c[i], c[i+step], baselineRatio)` 求基线，最后一条用前一条间距外推；
    `guideIdx += linesPerRow`，用尽 `flushPage()` 后归零（每页排版相同）
  - `alignToGrid` 在 guide 启用时强制关闭；有背景照片时不再把程序纹理画在照片上
- `config.{hpp,cpp}`：8 个 `line_guide_*` 键

### 实施中新发现的既有 bug（重要）

`Config` 的 double 数组若值**恰好全是整数**，`load()` 会存成 intArray，`getDoubleArray` 返回空
→ 锚点 `bg_calib_points`、导引曲线 `line_guide_curves` 这类整数像素坐标会整组丢。
修复：`getDoubleArray` 遇到 intArray 时统一转 double。加了回归用例。
→ 教训：**同一种数据可以有两种存储形态**，getter 必须兼容，别只测小数路径。

### 本批揪出的既有 bug（重要）

**CLI 加载预设时背景锚点校准永远不生效**：`cli.cpp` 里写的是
`cal.enabled = cal.isValid();` —— 而 `isValid()` 自身要求 `enabled` 为真，
于是刚填好的网格立即被判无效、锚点被静默丢弃。GUI 路径没这问题（它先设了 `enabled = true`）。
已在 CLI 改为先置真再校验，并在 `BackgroundCalibration::isValid()` 上加了显式注释。
→ 教训：**「先赋值再自校验」的顺序陷阱**，以及 CLI 与 GUI 两条路径要对称测试。
