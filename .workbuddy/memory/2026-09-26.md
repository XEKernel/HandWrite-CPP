# 2026-09-26 工作记录

## Line Guides 批次 4 补充完善（v2.9.0 未发版）

用户说「继续完善，昨天由于更换了模型，可能受模型水平限制」—— 回头审查昨天的代码，
确实揪出 4 处缺陷，已全部修复。

### 修复 1：`LineGuideSet::build()` 不保证关键曲线有序（**CLI 路径全错**）

- 排序（按垂直位置）只做在 `LineGuideDialog::sortKeyCurves()` 里，**引擎层没有**。
- CLI 从预设文件读进来的顺序完全取决于文件内容，一乱就会在两段相距很远的曲线之间插值。
- 修法：`build()` 内部统一 `prepareKeyCurves()` —— 丢弃不可用曲线、
  每条 `normalize(0)`（排序 + 去重，**不平滑**，保持原始形状）、整组按 y 均值 stable_sort。
- 验证：两条关键曲线正序/逆序各写一份预设，渲染两图比 MD5 → **完全一致**（修复前不同）。

### 修复 2：拖拽曲线时会拖到别的曲线上

- `mouseMoveEvent` 每帧调 `refresh()` → `sortKeyCurves()` → 数组下标变化，
  而 `m_selCurve` / `m_dragSnapshot` 都是按下标索引的 → 拖的不再是原来那条。
- 修法：`refresh(bool structural = true)`，拖拽时传 `false`（跳过排序与按钮状态刷新）。

### 修复 3：检测曲线两端带纸外垃圾段

- 纸外列块找不到横线时保留等距初值（`curY`），而初值有累积误差 → 末条横线偏 10px。
- 修法：跟踪时记录 `valid` 标志 → 裁掉首尾无效段 → 中间被遮挡的列块用前后有效点
  线性插值补回 → 有效点不足 1/3 的整条丢弃（并在 message 里报告丢弃条数）。
- 效果：末条曲线 y 由 1150 → **1140**（正确），x 范围 [81,819]（不再含纸外），dev 0.015 → 0.005。

### 修复 4：只画 1 条关键曲线时点确定会静默失效

- 插值模式要求 ≥2 条，判定无效后导引不生效，但用户只看到"画了线却没反应"。
- 修法：确定时校验，弹出提示并给出两条可选做法（再画一条 / 取消勾选自动插值）。

### 附带修复

- **中间偏差的评估区间**：曲线裁切后各条 x 范围可能不同，原先整条中间曲线拿去和首尾
  插值比，超范围部分被 `yAt()` 夹取端点 → 偏差偏大。改为只在三者**共有 x 区间**采样。

### 体验改进

- Ctrl+Z 撤销（`ev->matches(QKeySequence::Undo)`，走平台标准快捷键）
- 检测期间挂等待光标 + 暂时禁用按钮（大图要扫全图像素，否则像卡死）

### 验证

- 零告警；`ctest` **182/182**（新增 12 项：build 顺序无关 2 组、点乱序排序 3 组、
  深色背景+纸外裁切 4 组，以及既有回归）
- 顺序无关性：正序/逆序预设渲染 → MD5 一致
- 轻量检测验证程序（`F:/dchk`，只链 core/config/tools + Qt Core/Gui，比拉 GUI 快得多）：
  first x=[243,657]、last x=[81,819]、dev=0.005 —— 确认纸外垃圾段已裁掉

### 评估后暂缓（已写入规划文档）

- **画布滚轮缩放**：高分辨率照片缩显示后手绘困难，目前靠 3× 放大镜。加缩放要改
  `ImageCanvasDialog` 基类坐标换算（`CalibrationDialog` 共用），有回归风险。
- **检测 ROI 框选**：多物件照片无法限定范围，靠纸外裁切部分缓解。
- `followCurve = false` 的实际语义是「y 仍跟随、字符不旋转」，与规划初稿写的不同，
  当前行为更实用，已更新文档以此为准。
